# CHJ 新着投稿メール

ユーザーは新着投稿のメール通知を希望し、通知先 fujii.masashi.4@gmail.com と、汎用のお知らせ・管理画面リンクだけを送る方針を承認済み。本文・写真・投稿者名は送らない。メールの具体的な件名・本文は有効化とテスト送信の前に提示する（AGENTS.md）。

## Architecture
Pagesの既存Worker/D1を継続し、内部Service bindingでメール専用Workerを呼ぶ。専用Workerは固定宛先だけにsend_emailし、公開URLを無効化。REST APIキーや新規パスワードは不要。送信元ドメインと本人メール確認の利用条件はCloudflare画面で確認し、DNSや有料契約の変更は勝手に実行しない。Dashboardでメールbindingの宛先制限項目がないことを確認したため、Dashboard配置時は固定コードで制限し、Wrangler用設定ファイルにはdestination_addressも指定する。

直接Pagesへsend_emailを設定する方法は公式の対応binding一覧にない。外部有料メールサービスへの移行は不要な契約・秘密値が増えるため採用しない。

## Behavior
- 投稿の保存と通知待ちレコード作成は同一DBトランザクション（INSERT trigger）で成立。既存投稿の一括通知はしない。
- 通知は新規保存後に1回試みる。honeypot・不正・制限超過・同一受付キーの再送で新規通知を作らない。
- 通知に失敗しても投稿受付は202で完了。送信状況は管理者だけが確認し、未送信分を手動で再試行できる。
- 短時間のleaseで同時送信を防ぎ、失敗後は待機して再試行。メール送信先サーバーによる受付と受信箱への到着を区別。通信切断等による重複可能性は残る。
- メール送信は明示的な有効化設定がある場合のみ実行し、初期状態は無効。管理画面には無効/設定不足/送信受付済み/再試行待ちを正しく表示。
- メール専用Workerは宛先・件名・本文・管理URLを固定し、呼出元から任意の宛先や本文を受け取らない。
